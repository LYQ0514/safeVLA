## 0.1 暂停决定（2026-11-01，追加）

本方案因**研究动机未获支持**而暂停，不进入 Source 候选续轨实验。依据：

- 采集 6 条 long task0 轨迹（显式源噪声），时间对齐分析（见关联文档）显示：
  - 「AEGIS 持续局部投影阻碍推进」这一推理第一环**未被支持**；
  - soup 未完成的主因是**策略提案不足**（5/6）与**抓取失败**（EP2），而非过滤阻碍。
- 冻结的 Source 生成器 `min‖Δz‖² s.t. 当前安全约束` 只修当前风险，
  **不鼓励接近 soup、改善抓取或完成剩余子目标**，与观察到的失败之间缺少作用机制。

> 若未来转向「任务导向候选搜索」，需先明确其相对「独立策略重采样＋任务评分」与
> 「动作候选＋同一评分」的必要性，再考虑使用源空间。本设计以下内容作为历史冻结保留，
> 供未来参考，不继续执行。

## 1. 研究问题（冻结）

> 在固定 AEGIS 后续控制、共同部署动作代价约束和候选评估预算下，源空间候选能否比
> 动作空间候选提供更好的起点，改善 long 任务的安全阶段推进？

要点：

- 「后续控制」固定为 AEGIS（CBF-QP 动作过滤器，保持其算法不变）。
- 「共同部署动作代价约束」——防止把「改得更多」误读为「改得更好」（继承
  PNSG ep06 教训：源空间小步长经非线性前向可放大为动作域大修正）。
- 「候选评估预算」——三组在相同候选数 / 相同评估次数下比较，不靠多搜索取胜。

## 2. 起点与动机（作为假设，不作为事实）

### 2.1 当前关注的失效模式（非结论）

AEGIS 复现观察到一个值得关注的失效模式：**long 套件上「安全但无用」**——CAR 从
14% 升到 68%，但 TSR 从 62% 崩到 14%，SSR 零收益（−0.5pp）。

这**当前只是待解释的观察**，不是已证实的根因。它是否由「反复 CBF 投影导致误差
累积」造成，需要：
- 干预记录（AEGIS 已有 `intervene_count` / `feasible_count`，但需按 long 套件分桶）；
- 阶段进度曲线（是否「靠近目标后被反复推离」）；
- 失败轨迹分析（失败前一刻的干预与几何状态）。

> 本设计**不**以「AEGIS 的弱点是反复 CBF 投影」为前提。若校准阶段发现该假设不成立，
> 本实验线的有效性需重新评估，而不是硬套。

### 2.2 源空间候选不天然具有前瞻性

源空间候选 = 在 π0.5 噪声空间 z 上生成的动作提案。它**没有**因为「改了源空间」就
自动具备前瞻性或绕行语义。若首版复用当前局部安全约束得到的 Δz*，那它仍然是在修
当前风险。

**前瞻性只能来自候选评估目标或闭环预测**（即 `V_future`），不能来自候选的生成空间。
这一点必须贯穿实现，防止「Source 提案」被默认为「有远见的提案」。

### 2.3 AEGIS 是部署动作过滤器，不是完整安全保证

AEGIS 的 CBF-QP 只做末端椭球单障碍物避障投影。已有 robot–environment 事件说明
（`docs/想法v10.md` §7）表明它不能自动承担完整系统安全。**最终候选仍须经过统一
非线性认证器（完整 C_2）**，AEGIS 只是「后续控制」这一环，不是认证。

## 3. 比较结构（冻结，三组最低结构）

| 组别 | 候选 | 选择方式 | 后续控制 |
|---|---|---|---|
| **G1 原 AEGIS** | nominal | 原规则（无前瞻选择） | AEGIS |
| **G2 Action＋前瞻选择** | 动作空间候选，含 nominal | 统一前瞻评分 | AEGIS |
| **G3 Source＋前瞻选择** | 源空间候选，含 nominal | 同一前瞻评分 | AEGIS |

- **G1** 衡量部署总收益（是否比现状更好）。
- **G2 vs G3** 辨别 Source 的**增量价值**（在前瞻选择相同的前提下）。
- 三组最终执行动作统一计算 `C_act`，记录累计代价与计算时间。
- **不靠事后挑「恰好代价接近」的成功样本**：预先设定共同代价上限或代价档位，
  在档位内比较。

### 3.1 候选生成（首版）

| 组 | 候选 |
|---|---|
| G1 | `{nominal}` |
| G2 | `{nominal}` ∪ 动作空间候选（复用 PNSG 的 Δa* 方向缩放） |
| G3 | `{nominal}` ∪ 源空间候选（复用 PNSG 冻结的 Δz* 方向缩放，**含 Δz=0**） |

- 候选是**安全提案**，不预设绕行或语义能力。
- G3 的 Δz=0 分支 = 原始策略输出，退化为 G1 的提案来源（但走 G3 的前瞻选择）。

### 3.2 AEGIS 角色（冻结）

**propose-then-filter**：

```
候选动作（Source/Action 提案）
    → AEGIS CBF-QP 投影（保持上游算法不变，只做接口适配）
    → 最终动作 A_exec
    → 统一非线性认证器（完整 C_2）
```

AEGIS 是「最后一道部署动作投影」，不是协同优化者。源空间候选与 AEGIS **不联合求导**，
避免两个控制器互相抵消。

### 3.3 两套约束的关系（冻结，不宣称等价）

| 约束 | 职责 |
|---|---|
| 提案约束（PNSG 多约束最小范数半空间，C,b） | 生成源空间 / 动作空间候选 |
| AEGIS CBF（单障碍物单椭球硬约束 + QP） | 部署动作过滤 |

两者**分别记录，各自承担提案生成与动作过滤职责，不宣称等价或互相包含**。

## 4. `V_future`：测量框架（待校准）

### 4.1 不压成单一加权分数

long 任务优先测量**可检验的独立量**：

1. **有顺序要求的阶段是否完成、完成时间**（long 套件有多阶段往返）；
2. **是否掉落、回退或停滞**；
3. **新的安全违反**（统一认证器下的完整 C_2）；
4. **后续累计干预代价与计算成本**。

EEF 距离只作为**阶段内辅助量**，不能替代多阶段任务推进。

### 4.2 校准门（下一步只做这个，通过前不扩实验）

对同一 snapshot、同一候选、同一配对续轨种子，检查：

1. 上述量**是否可复现**（同一输入多次续轨，结果是否一致）；
2. 候选间差异**是否大于重复波动**；
3. 有限 horizon 内**是否出现有效阶段变化**（不是恒零、也不是纯噪声）。

**达不到任一条件 → 停止当前前瞻选择设计**，不扩实验，也不靠不断拉长 horizon 找信号。

### 4.3 短期评分与最终 TSR/SSR 分离

候选的短期前瞻评分 与 最终 TSR/SSR **分开测量**。前者能否预测后者，本身就是校准
要回答的问题——**不得预设它们相关**。

## 5. 部署代价与计算成本（冻结口径）

- 最终执行动作统一计算 `C_act`（部署 pose 相对 nominal 的 L2，clipping 后）；
  有 clipping 时用实际部署动作重算，不套缩放平方关系（继承 `docs/testing/pnsg_cost_match.md`）。
- 记录每组的累计 `C_act`、策略调用次数（含 Jacobian / 求解 / 前向）、总计算时间。
- 共同代价上限 / 代价档位在测量校准后冻结。

## 6. 解释边界（冻结）

| 结果 | 支持的解释 |
|---|---|
| 两种前瞻选择都优于 G1、彼此接近 | 支持前瞻选择，**未支持** Source 的额外价值 |
| Source 在共同代价与预算下优于 Action | 支持该范围内的源空间候选贡献 |
| 收益伴随更大动作代价或更多计算 | 先报告权衡，**不能归因于方向优势** |
| 评分不稳定或无法区分候选 | 测量门未通过，**不能判定方法有效或无效** |

---

## 7. 与已收口 PNSG 结论的继承关系

本设计继承三条约束（来自 `docs/testing/pnsg_steering_final_report.md`）：

1. **必须比较总部署动作代价**（防止幅度效应重新混入）；
2. **必须保留 nominal / Δz=0 分支作为零假设基线**（G1 即基线）；
3. **必须允许 Source 贡献为零**（G2 与 G3 无差异是合法结论）。

本设计**不**继承 PNSG 的结论「源空间无相对优势」——那是在**动作空间修正 + 两步认证**
协议下的结果；本设计换了「后续控制（AEGIS）+ 前瞻选择 + long 任务」三个条件，
是新的可证伪主张。
