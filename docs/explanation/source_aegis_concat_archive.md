# Source→AEGIS 串接实现归档（止损收尾）

> 日期：2026-11-01
> 状态：**暂停规模扩展**。链路已实现并冒烟，但增益机制未建立，成本高，不继续跑全量。
> 代码：
> - `src/safety/source_aegis.py`（SourceAegisPolicy：源空间 steering 提案 + AEGIS 过滤）
> - `tools/run_eval_source_aegis.py`（冒烟 + 批量评测入口）
> 结果：`data/eval/source_aegis_smoke_test/`（5 episode 冒烟）

---

## 一、串接链路（实际实现，非前瞻联合）

```
每个重规划点（replan=5）：
  1. z0 = nominal_seed 采样；nominal = clip(π0.5(z0))
  2. 危险检测：球体代理（8 link + 指尖，半径 0.02m）预测 nominal 是否净空 < 5mm
  3. 危险时：J = jacfwd(∂动作/∂z)；解 min‖Δz‖ s.t. C·J·Δz ≥ b；z_cand = z0+Δz；
     steered = clip(π0.5(z_cand))
  4. 取前 replan_steps 步，逐步过 AEGIS CBF-QP 过滤后执行
```

**这不是之前讨论的前瞻联合方法**：它做的是「当前几何风险 → 局部 Source 修正 →
AEGIS 过滤」，没有评估候选执行后的任务推进，也没有解决短视性。

## 二、执行边界（已核实，必须准确记录）

1. **每次重规划生成 10 步 chunk，只取前 5 步执行**，队列空再重规划。
2. **`act()` 只做 AEGIS filter，没有 C_2 认证**。
   因此**不能继承「认证后执行」的安全表述**——本实现是「AEGIS 过滤后执行」，
   不是「统一非线性认证后执行」。
3. AEGIS filter 逐步调用；steered 的 5 步前缀**未做统一 C_2 认证**。
4. 此前 PNSG 的 C_2 只认证两步；本实现执行五步且无 C_2 认证，二者不一致，
   报告不得混用。

## 四、单案例 ep35（真实危险 episode）

- 基线 π0.5：碰撞 12.15 mm，成功，149 步。
- Source+AEGIS：无碰撞（0.002 mm），成功，264 步；steer=8，无 infeasible。

**边界**：这是「组合链路」的单案例，**没有同状态、同噪声、同 AEGIS 状态的基线对照**，
也没有「同全臂检测 + 同认证 + 同代价约束的 Action repair＋AEGIS」对手。
因此 ep35 的「12mm→0」**不能单独支持 Source 的必要性**（代价匹配已说明单点 Source
成功可能由动作修正幅度解释）。

## 五、方法诊断（三处校正，已采纳）

1. **全臂覆盖本身不是问题**：某 link 可能撞障碍（末端安全），AEGIS 的 robot–environment
   观察正说明不能只保护末端。因此「比末端 CBF 检查更多」不能直接解释为过度保守。
   55/63 次触发是否「误报」，需区分几何误差 / chunk 预测与执行的时间差异 /
   末端 CBF 未覆盖的真实全臂风险；**没有原生几何与同状态执行证据，不能下结论**。
2. **当前串接不是前瞻联合**：见 §一。继续跑它只能评估一种新的局部修正组合，
   不能验证「Source 帮 AEGIS 选择更好的长期起点」。
3. **组合提高 CAR ≠ Source 有贡献**：相比原 AEGIS，本实现多了全臂检测和额外修正机会。
   要归因源空间，对手应是「同全臂检测 + 同认证 + 同代价约束的 Action repair＋AEGIS」。

## 七、结论（冻结）

> 当前 Source→AEGIS 串接实现已运行，但触发机制的风险辨别能力尚未量化，计算开销较高，
> 且源空间相对同条件动作修正的增量价值未建立。因此停止规模扩展。

## 八、重新立项条件（冻结）

未来只有出现**新的、可检验的机制**或**明确失败案例**，才重新立项；
不再以「跑完基准就可能看出价值」为理由追加预算。
