## 建议冻结的 Contact Contract

### 1. 分类与“是否允许”必须分离

不要在 recorder 中直接丢弃 robot–target 或 target–goal contact。每条 native contact 先做纯语义分类，再单独赋予允许状态：

```json
{
  "semantic_class": "ROBOT_TARGET",
  "allowance": "ALLOWED_BY_TASK_STAGE"
}
```

这样能防止错误的 allowed rule 把真实事件静默删除。

### 2. 每条 contact 的基础字段

```text
episode_id
control_step
physics_substep
geom1 / geom2
body1 / body2
instance1 / instance2
role1 / role2
semantic_class
contact_dist
preexisting_at_snapshot
task_stage
allowance
role_manifest_sha256
contract_version
```

角色顺序必须无关：

```text
ROBOT ↔ DISTRACTOR
DISTRACTOR ↔ ROBOT
```

应产生相同分类。

### 3. 语义类别

建议至少冻结：

```text
ROBOT_STATIC_OBSTACLE
PAYLOAD_STATIC_OBSTACLE
ROBOT_DISTRACTOR
DISTRACTOR_STATIC_OBSTACLE
ROBOT_MANIPULATED_TARGET
MANIPULATED_TARGET_GOAL
ROBOT_GOAL
PAYLOAD_DISTRACTOR
DISTRACTOR_GOAL
ROBOT_SELF
ROBOT_ENVIRONMENT
OBJECT_ENVIRONMENT
OTHER_UNCLASSIFIED
```

其中前四类是当前 CAR 来源分解的核心机制。

建议不要只用六个硬编码分支。底层保存通用 `role_pair`，上层再映射到机制类别，方便复杂任务扩展。

## 4. 接触记录分三级

MuJoCo `data.contact` 可能包含 margin 内的 proximity contact，因此建议同时记录：

```text
native_contact_record = contact 存在
geometric_contact     = contact.dist <= 0
proximity_only        = contact.dist > 0
```

主机制审计建议优先使用：

```text
geometric_contact
```

同时保留全部 native records 做敏感性分析。

如果已经可靠记录 `mj_contactForce`，可额外保存：

```text
normal_force
solver_active
```

但不要临时挑一个 force threshold。若使用 threshold，必须先用 calibration 数据冻结。

## 5. Allowance 规则

建议使用：

| Semantic class | 默认状态 |
|---|---|
| `ROBOT_STATIC_OBSTACLE` | `FORBIDDEN` |
| `PAYLOAD_STATIC_OBSTACLE` | `FORBIDDEN` |
| `ROBOT_DISTRACTOR` | `ENVIRONMENT_DISTURBANCE` |
| `DISTRACTOR_STATIC_OBSTACLE` | `SECONDARY_DISTURBANCE` |
| `ROBOT_MANIPULATED_TARGET` | `TASK_CONTACT`，保留记录 |
| `MANIPULATED_TARGET_GOAL` | 仅满足对应 goal/stage 时 `ALLOWED_BY_TASK_STAGE` |
| `ROBOT_GOAL` | 不自动允许，按任务规则决定 |
| `ROBOT_SELF` | `FORBIDDEN` |
| `OTHER_UNCLASSIFIED` | `UNKNOWN`，门禁失败 |

不要把所有 robot–target 全局删除，也不要把所有 target–goal 全程允许。

## 6. 初始接触规则

在执行前 snapshot 上保存初始接触集合：

```text
initial_contact_pairs
```

运行中的接触标记为：

```text
NEW_CONTACT
PREEXISTING_CONTACT
PREEXISTING_WORSENED
```

本轮 CAR 来源审计至少应将 preexisting contact 与新接触分开。否则初始穿透会被误认为方法造成。

## 7. 连续事件合并

raw substep records 不能直接作为统计单位。

对同一：

```text
episode
geom pair
semantic class
```

在连续 physics substeps 上出现的 contact 合并为一个：

```text
contiguous_contact_event
```

建议不跨缺失 substep 合并，即 gap tolerance 固定为 0。

每个事件记录：

```text
start_control_step
start_substep
end_control_step
end_substep
duration_substeps
minimum_dist
maximum_penetration
```

## 9. CAR 来源关联

对每个 episode 先找到官方 CAR 首次触发时刻：

```text
t_CAR = 第一次出现 L1 displacement > 1 mm 的时刻
```

然后报告：

```text
mechanisms_before_or_at_t_CAR
first_mechanism_before_t_CAR
mechanisms_after_t_CAR
```

一个 episode 可以多标签：

```text
ROBOT_STATIC_OBSTACLE
ROBOT_DISTRACTOR
DISTRACTOR_STATIC_OBSTACLE
```

这些比例之和允许超过 100%。

除非做了同状态 counterfactual，否则使用：

```text
ASSOCIATED_WITH_CAR_TRIGGER
```

不要使用：

```text
CAUSED_CAR_TRIGGER
```
