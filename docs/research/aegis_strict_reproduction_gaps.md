# AEGIS 严格复现差距清单（诚实回答「是否严格复现」）

> 日期：2026-11-04。回答：**不是严格复现**。除已修复的四元数 bug 外，仍存在多处
> 与上游 AEGIS 的偏差。本文件逐一列出，作为「重做」前必须对齐的清单。

---

## 0. 直接回答

**不是严格复现。** 当前实现（即使修复四元数 bug 后）与上游 AEGIS 存在 **5 处偏差**，
其中 2 处是「有意的 oracle 化」（已在文档声明），3 处是「未对齐上游」的参数/逻辑偏差。
因此，正在跑的全量 baseline（`aegis_1024_fixed`）**仍不能声称是 AEGIS 的严格复现**，
只能算「修复了最严重 bug 后的近似复现」。

## 1. 完整差距清单

| # | 维度 | 上游 AEGIS | 我的实现 | 类型 | 影响 |
|---|---|---|---|---|---|
| 1 | 四元数约定 | `R.from_quat`（xyzw） | 曾误当 wxyz | bug | ✅ 已修复 |
| 2 | **策略输入分辨率** | 渲染 1024 → **resize 224** 喂策略 | 渲染 1024 → **resize 1024** 喂策略 | **偏差** | **中**（π0.5 训练用 224，1024 输入是 OOD） |
| 3 | **p2 刷新** | fit_ellipse 一次，**episode 内固定** | 每步刷新 obs 位姿 | 偏差 | 中（我更保守，但不同） |
| 4 | **num_steps_wait** | **20** | **10** | 偏差 | 轻（物体落稳程度不同） |
| 5 | 障碍物几何 | MVEE 点云拟合 | MuJoCo geom 真值 | oracle 化 | 中（真值更准，但非复现） |
| 6 | 障碍物识别 | VLM+GroundingDINO | oracle（工作空间第一个 obstacle） | oracle 化 | 中（非复现） |

## 2. 各偏差的详细说明

### 2.1 策略输入分辨率（偏差 2，最可能影响评测）

- 上游：`LIBERO_ENV_RESOLUTION=1024` 渲染，`resize_size=224`（`image_tools.resize_with_pad`
  缩到 224×224）喂给 π0.5；
- 我的 `run_eval_aegis.py --resolution 1024`：`image_size=1024`，即 `libero_image(..., 1024)`
  把图像 resize 到 1024×1024 喂策略；
- **π0.5 的 LIBERO checkpoint 训练分辨率是 224**，喂 1024 是显著的 out-of-distribution，
  会改变策略行为。这是「策略输入」层面的偏差，与 AEGIS 过滤器无关，但会影响整个评测。

### 2.2 p2 刷新（偏差 3）

- 上游：`p2 = fit_ellipse(...)` 只算一次（第 227 行），整个 episode 用固定 p2；
- 我的 `filter()` 每步 `self.p2 = obs[name+"_pos"]`（第 522 行）；
- 静态障碍物（mug 不被碰动）下两者等价；障碍物被碰动后，我跟踪新位姿（更安全），
  上游用旧位姿（保护错位）。方向是「我更正确」，但不是复现。

### 2.3 num_steps_wait（偏差 4）

- 上游 20 步空转，我 10 步。物体落稳程度不同，影响初始位形。

### 2.4 障碍物几何 + 识别（偏差 5/6，oracle 化）

- 上游用视觉感知（GroundingDINO 检测 + 深度点云 + MVEE 拟合），我用 MuJoCo 真值；
- 这是「oracle 化」，文档已声明「不能直接对比论文数字」，但**严格意义上不是复现**。

## 3. 结论：当前全量 baseline 的性质

正在跑的 `aegis_1024_fixed` 是「**修复了四元数 bug 后的近似复现**」，仍含 5 处偏差。
它不能回答「AEGIS 论文的真实性能」，只能回答「修复主要 bug 后，我们的 AEGIS 实现的
真实性能」。

## 4. 若要严格复现，需对齐的清单

1. **策略输入 resize 224**（最关键）：改 `run_eval_aegis.py` 让策略输入缩到 224，
   与 π0.5 训练一致（渲染仍可 1024，但喂策略前 resize 224）；
2. **p2 固定**：改 `filter()` 让 p2 在 reset 后固定，不每步刷新（对齐上游）；
3. **num_steps_wait=20**：对齐上游；
4. **障碍物几何/识别**：若要完全复现，需接入 GroundingDINO + 深度点云 + MVEE
   （工程量大；若只对齐「过滤器数学」，可保留 oracle 但明确标注）。

## 5. 诚实声明

- 我之前「修复了四元数 bug」是**必要但不够**的——还有 5 处偏差未对齐；
- 尤其「策略输入分辨率 1024 vs 224」是一个**此前完全没意识到**的偏差，它影响的是
  π0.5 的策略行为（与 AEGIS 过滤器无关），可能显著改变评测结果；
- 因此，「重做」的范围需要扩大：**不仅重跑 AEGIS baseline，还要先对齐这 5 处偏差，
  才能真正声称「严格复现」**。
