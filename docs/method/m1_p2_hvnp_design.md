# M1-P2：Horizon-Verified Nominal Preservation（HVNP）设计

> 日期：2026-11-01
> 状态：方法设计。Oracle 原型阶段，非可部署算法。
> 前置：`m1_p1c_g3_h10_negative_result.md`（单步表面梯度闭环失败）。

---

## 0. 方法定位

G3 的负结果证明单步几何梯度的闭环预测安全不足，并揭示一个更有价值的信号：

> **在相同起始状态下，原始名义执行（N）可能比 AEGIS 过滤后的闭环执行（B）更符合 CAR**
> （N 0.035mm vs B 1.032mm）。

HVNP 不再对局部表面距离贪心优化，而是从**固定的有限候选序列集合**中选择满足安全
契约的方案。核心原则：

> **优先保留经过短时域验证的 π0.5 名义动作；只有名义执行存在真实物理风险时，
> 才选择经过验证的替代动作序列。**

既不默认名义动作危险，也不默认 AEGIS 一定更安全。

## 1. 核心数学定义

固定候选控制序列集合：

$$\mathcal U_H(s_t) = \{ U^N,\ U^A,\ U^{Z+A},\ U^{L+A},\ U^{Hold+N},\ \ldots \}$$

每条序列在**自身分叉后的新观测**下执行正确的 π0.5 重规划（replan_steps=5 原始时序），
不缓存原始未来动作。

预测：

$$\hat X_H(U) = \mathcal F_H(s_t, U; \pi_{0.5})$$

安全契约筛选：

$$\mathcal U_H^{safe} = \{ U \in \mathcal U_H : C_{body}(U)=0 \ \wedge\ D_{max}(U) < \delta_{CAR} - \epsilon \}$$

两级选择：

$$U_H^* = \begin{cases} U^N, & U^N \in \mathcal U_H^{safe},\\[2mm] \arg\min_{U \in \mathcal U_H^{safe}} J_{dev}(U), & \text{否则}. \end{cases}$$

- $J_{dev}(U) = \sum_t \| a_t^{exec}(U) - a_t^{nom}(U) \|$：相对冻结 π0.5 名义行为的
  干预程度（在 U 自身分叉轨迹内逐步比较）。
- 无安全候选 → 显式报告 `NO_VERIFIED_SEQUENCE`，**不**隐式回退到未验证安全的 AEGIS。
- 第一版**不使用**仿真器 soup 真值做在线任务奖励优化（避免特权目标位置入方法）；
  任务进度/成功率仅作为评价指标。
- H 步预测仅支持有限时域安全，不构成整个 episode 的安全保证。

## 2. 候选序列字典（第一版，冻结）

| 候选 | Step t=0..H-1 动作 | 干预模式 |
|---|---|---|
| N | 名义 | 无干预 |
| A | AEGIS 过滤 | 全程过滤 |
| Z+A | 前 2 步 +z 抬升（0.4），后 AEGIS | 抬升避让 + 过滤 |
| L+A | 前 2 步侧向（0.4，固定 L− 方向），后 AEGIS | 侧向避让 + 过滤 |
| Hold+N | 前 2 步 Hold，后名义 | 停止 + 名义接续 |

方向与幅度**全部冻结**（沿用 G3 已验证的 Z/L−/Hold），不新增方向、不调幅度。

## 3. 与局部梯度方法的区别（为何更合理）

G3 的三个区别性例证：

- **N**：Dmax=0.035mm → 完全不干预可以是很好的安全选择；若满足禁止接触，应直接选 N。
- **G-N**：Dmax=1.889mm → 单步增加碰撞间隙不足以预测后续连杆运动与控制响应。
- **Z+A**：Dmax=0、Δd_soup=−27.2mm → 预定义替代序列可行，但未证明比所有其他安全候选更优。

## 4. 关键技术点

1. **两类场景必须同时通过**：
   - 名义安全时，避免多余干预；
   - 名义有真实风险时，从替代序列中找安全且任务有效的方案。
   否则只是重新包装 M0 的名义动作保留。
2. **固定案例的局限**：Step54 若名义已安全，HVNP 正确选择可能就只是 N，这能检验
   「避免不必要过滤」，但不能单独证明「几何替代动作的选择能力」。
3. **AEGIS 作为候选而非 fallback**：A 进入 $\mathcal U_H$ 作为待验证候选，只有通过
   安全契约才可选；不因它是「安全过滤器」就默认安全。

## 5. T-RO 创新边界

「离散候选 + 短时域 Oracle 验证」与采样式 MPC / 预测安全过滤 / 模型预测屏蔽存在
明显联系，本身不足以作 T-RO 创新。它更适合作为**可靠上界**，用于研究两个真问题：

1. 如何以很低的额外推理与物理计算开销，判断冻结 VLA 的名义动作是否需要干预？
2. 如何在真实全身几何与历史安全契约下，选择既安全、又不破坏后续 VLA 重规划能力的动作？

第 2 问与「恢复感知安全干预」主线一致：不只看当前动作修正幅度，还看干预后冻结
策略是否仍能继续完成任务。

## 7. P0 验收标准

| 验收项 | 通过条件 |
|---|---|
| 安全契约 | 全身禁止接触 + episode 历史 CAR，用 sim.data 真值 |
| 选择优先级 | 名义安全时优先 N，否则选干预最小的安全序列 |
| 无解语义 | 无候选时报告 `NO_VERIFIED_SEQUENCE`，不伪造 |
| 真实接续 | 候选分叉后重新 generate π0.5，保留动作块/CRN 时序 |
| 计算开销 | 报告每次决策的预演次数、π0.5 推理次数、耗时 |
| 区分能力 | 在名义安全场景避免干预，在名义危险场景找到安全替代 |
