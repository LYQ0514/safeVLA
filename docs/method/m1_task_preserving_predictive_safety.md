## 0. 方法定位

M1 从「单步安全验证」升级为「有限时域任务保持型安全动作选择」，
统一解决两个已观察问题：
- **过度干预**（TSR 损失）：保守末端椭球排除安全名义动作；
- **保护遗漏**（CAR 风险）：只保护末端，漏掉 link6 连杆。

核心不是「无限增加预演时域」，而是对**少量、由真实碰撞几何生成**的候选序列
做物理验证，选「安全 + 推进任务」的序列。

## 1. 数学定义

扩展状态 $\xi_t = (x_t, p_0, D_t)$，候选序列 $A = a_{t:t+H-1}$。

安全可延续集合：

$$\mathcal S_H(\xi_t) = \{ A : \text{未来 }H\text{ 步满足全身安全 } \wedge \text{ 历史 CAR 不超限} \}$$

选择：

$$A_t^* = \arg\min_{A \in \mathcal S_H(\xi_t)} [ J_{nom}(A) + \lambda J_{task}(A) ]$$

其中：
- 全身安全：所有 robot link（含 link6）+ 附着物体的禁止接触 = 0；
- 历史 CAR：$\hat D_{t+k} < \delta_{CAR} - \epsilon$（固定 ε，不调参）；
- $J_{nom}$：与名义序列的距离；
- $J_{task}$：任务进度（方向/阈值按具体定义，不含特权 soup 坐标）。

## 2. 候选生成（关键，避免 C2 陷阱）

候选**必须由真实碰撞几何生成**，不能随意扰动动作后挑成功结果：

- Nominal 序列（π0.5 名义）；
- AEGIS 序列（保守过滤）；
- **几何侧向避让**：沿「link6 与 mug 的最近分离方向」调整末端运动，
  使 link6 避开 mug（由 MuJoCo 几何计算，非任务奖励驱动）；
- **退让/抬升**：沿竖直方向抬升末端，使 link6 越过 mug 高度；
- Hold（停止，作为安全回退）。

> 候选的「方向」来自真实几何（link6-mug 分离向量、障碍物边界），
> 不是「朝 soup」这种任务方向——避免重蹈 C2「强制朝物体中心」的错误。

## 3. 与已有方法的技术区分

- 全身 CBF（VLPSA/WBAG）：已覆盖「全身几何」，不是创新；
- M1 候选价值在「native 契约一致 + 任务保持选择 + 有限时域物理验证」三者结合，
  尤其「由几何生成避让候选」而非「QP 方向约束」。

## 4. 三项待验证贡献目标

1. Contract-consistent safety（CAR + 禁止接触 + 历史状态一致）；
2. Task-preserving action selection（保留安全名义 + 几何避让）；
3. Efficient predictive verification（高效代理替代 Oracle + 误差界）。

## 5. 实验安排

| 阶段 | 范围 | 问题 |
|---|---|---|
| M1-P1 Design Gate | step54（接触前）固定状态 | 短时域候选能否安全 + 保持进度 |
| M1-P1 闭环 | 全时域 | 能否恢复 soup + 保持 CAR + 选择性过滤 |

预先固定：预测时域 H、候选生成规则、安全裕度 ε、评价方式。
不根据最终成功反复选有利参数。

## 6. 边界（Oracle 阶段）

- 用 MuJoCo 复制状态预演，是仿真特权验证器，非可部署；
- 不保证未来所有动作安全（有限时域）；
- 无候选时记录 NO_VERIFIED_SEQUENCE，不伪造。
