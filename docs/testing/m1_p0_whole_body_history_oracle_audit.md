## 4. Step62 的关键诊断区分

`NO_VERIFIED_ACTION` 有两种可能（不能混同）：

1. 所有候选确实继续造成危险接触；
2. 接触在**状态入口已存在**，即使某动作能逐渐解除接触，也因预测窗口内检测到接触被拒绝。

需区分：
- $C_t^{entry}$（动作执行前已存在禁止接触）；
- $C_{t:t+1}^{pred}(a)$（候选执行期间出现禁止接触）。

不能为让候选通过而放宽硬安全条件；恢复控制应作为单独模式研究。

## 5. Step63 的余量问题

$$B_{63} = 1 - 0.89 = 0.11\text{mm}$$

即使 step63 名义动作通过单步检查，也不能据此认为未来有足够安全余量。
过去发生的接触不能因当前无接触而从历史消除。
