## 0. 结论（一句话）

> 三个候选机制（跨控制步目标记忆 / 采样间接触违规 / 力矩饱和）在 task0 当前实例上
> **均未获得有效见证**。控制接口、执行链、力矩路径均已核查成立，但未发现「执行动态
> 引入额外安全风险」的实证证据。当前路线暂停；「安全约束的物理可实现性」保留为
> 控制理论候选问题，不作为已确立的新研究方向。

## 1. 三项结果汇总

| 假设 | 实验 | 判断 |
|---|---|---|
| 历史 `goal_pos` 影响下一控制步 | A0：`achieved` 语义覆盖旧目标 | 不成立 |
| 参考保持期间发生采样间碰撞 | S0：25 substep 无接触，3 次一致 | 当前实例未发现 |
| 力矩饱和导致执行偏差 | S0-F4：0/25 饱和，τ_requested=τ_clipped=qfrc_actuator | 当前实例不成立 |
| OSC 执行动态产生安全相关影响 | 有跟踪误差 0.029→0.023，动态收敛 | **尚未得到有效判断** |

## 2. 关键区分（不夸大负结果）

- **无饱和 ≠ 无执行动力学**：`τ_applied = τ_requested` 只说明力矩路径无失真，
  不说明 `x_{k+25} = F_kinematic(x_k, a_k)`（无动力学）。
- 实测 `e_track = ||goal_pos − ee_pos|| = 0.029 → 0.023`（约 2.9cm→2.3cm），
  说明 OSC **确实在做一个有动态响应的目标跟踪过程**。
- 但**没有证据表明这种动态差异造成了安全问题**——这才是正确的负结果。

## 3. 原始假说的根本问题（诚实指出）

原推理：

> 外部安全控制器没有显式建模 OSC 执行动态 → 因此可能发生执行期安全违规。

**缺失环节**：没有显式建模某动力学，不意味着该动力学一定造成实际安全失效。
AEGIS 的保守几何代理 + OSC 闭环反馈 + Panda 执行器配置 + SafeLIBERO 任务速度分布，
可能已共同形成足够大的实际安全余量。

**不为证明理论缺口而刻意寻找极端状态。**

## 4. 研究问题的可能调整

原问题：如何修复 VLA 安全层与 OSC 执行动态之间的失配？

更一般的问题：

> 什么条件下，外部参考指令的安全可行性可以传递为真实闭环执行的安全性？

后者数学上更扎实，但与 sampled-data CBF、Proxy CBF、鲁棒跟踪控制高度相关。
**仅凭当前数据，不足以建立新论文贡献。**

## 5. 保留 / 未成立

| 状态 | 内容 |
|---|---|
| 已成立 | 控制接口、目标更新、25-substep 执行、力矩限幅路径、当前实例执行一致性均经核查 |
| 未成立 | 当前实例无「跨控制步隐藏记忆 / 力矩饱和 / 采样间接触违规」的有效见证 |
| 保留问题 | 外部安全指令能否在一般 OSC 执行状态下获得可计算的安全实现保证（理论候选）|
| 项目建议 | 暂停当前案例扩展，不启动新控制器开发 |

## 6. 尚未测得的量（诚实缺口）

- **连续执行区间的几何距离裕量**：MuJoCo 2.3.7 无 `mj_geomDistance`，
  非接触时正表面距未知；$b_{geom}$、$\Gamma_{25}$、$M_{exec}$ 目前**不可数值计算**。
- 因此「几何模型提供多少真实余量 / 内环消耗多少 / 剩余是否够」三层中，
  只有「接触与否」可测，正余量数值未测得。

## 7. 下一轮选题要求（方法转变）

**停止**：「找到现有算法未建模的因素 → 假设它造成失效 → 用大量实验找支持案例」。

**转向**：先找「正常工作分布中稳定存在、同时影响物理安全与任务完成的控制冲突」，
再选 CBF / MPC / 可达性等方法解决。

- 现象不必先出现碰撞；可表现为安全可行域缩小、操作精度下降、任务无法推进。
- 但必须有清晰的物理量 + 反事实对照。

> 核心判断：我们不是必须找到一种新安全算法，而是需要找到一个**值得新安全算法
> 解决的问题**。当前路线在这一点上尚未交出足够强的证据，故暂停。
