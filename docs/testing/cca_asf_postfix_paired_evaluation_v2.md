## 4. 核心结论

### 4.1 修复 bug 后结论反而更清晰

| | v1（跨窗口 bug） | v2（正确实现） |
|---|---|---|
| cca mug 均值 vs euclidean | 17.9 vs 11.5（Δ+6.4） | 36.2 vs 12.0（Δ+24.2） |
| Δ>0 占比 | 2升2降（S01 不稳） | **13/16，4/4 state 一致** |
| 方向稳健性 | 弱（n=4 噪声主导） | **强（4/4 state 同向）** |

**v2 消除了 v1 的「方向不稳」，暴露出清晰的系统性趋势**：CCA 在 mug 保护上
**系统性地劣于 euclidean**，且 TSR 无提升（13 vs 14，反而略降）。

### 4.2 物理机制解释（可报告）

CCA 的设计目标是「少干预、保任务方向」。Pilot v2 证明了这个 trade-off 的真实代价：

> 修复后正确实现下，CCA 的「少干预」以「障碍物碰撞更严重」为代价：
> 介入更少（141 vs 160），但 mug 位移更大（4/4 state），TSR 无收益（13 vs 14），
> 极端情况下（S01/st0）出现 336mm 灾难性碰撞。

这与规格 §12 的禁令完全吻合，且现在有了实证：「CCA 每次干预更少所以更安全」是**错误**的，
**少干预 = 更危险**。

### 4.3 非确定性 caveat（仍存在，但不改变方向）

v1 与 v2 的 euclidean 绝对基线有差异（S01/st0 eu: 7.8mm → 20.1mm），说明跨进程
基线漂移仍存在。但：
- v2 是**单进程**跑的（无 GPU 并发），配对对照自洽；
- 4/4 state、13/16 对的同向趋势，远超单点噪声水平，**方向稳健**。

## 5. 最终裁决（更新）

1. **「CCA 有害（灾难性，27-30mm vs euclidean 0）」**：已洗清——四元数 bug 假象；
2. **「CCA 有效（TSR↑）」**：**证伪**——TSR 13/16 vs 14/16，无提升；
3. **「CCA 无害」**：**证伪**——正确实现下 CCA 系统性地碰撞更严重（4/4 state mug
   位移更高），且含 336mm 灾难性个例；
4. **机制结论（成立）**：CCA 的「各向异性方向重分配」在数学上成立（QP 层），但在
   真实闭环中，它把安全修正从「保护障碍物」重分配到「保任务方向」，结果**既没保
   住任务（TSR 无提升）也没保住安全（碰撞更严重）**。

**CCA-ASF 应归档为「机制成立、闭环无效且有害」**——与修复前的「数学成立、闭环
安全失效」判决相比，方向一致，但现在的证据建立在正确几何 + 正确方向提取之上，
更可靠。

## 6. 边界与诚实声明

- n=16 仍是小样本，336mm 极端值是单点，不能过度外推；
- 但 4/4 state 同向 + 13/16 对同向，是稳健的信号，不是噪声；
- 若要发表级结论，建议扩大到完整 50 init states + 更多 stream，并做配对 bootstrap
  检验（脚本已含 `paired_bootstrap`，未在此轮启用）。
