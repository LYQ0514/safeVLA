# PNSG 代价匹配诊断（source-only 状态）

> 日期：2026-11-01
> 性质：结果后提出的**探索性解释分析**，不改写 12 状态批次结论
> 数据：`/data/safeVLA/data/audit/cost_match_result.json`
> 脚本：`tools/pnsg_cost_match.py`

## 摘要结论（准确表述）

> 对 12 状态批次中的两个 source-only 状态做代价匹配：沿原 Action 修正方向 Δa* 缩放
> 幅度，使 clipping 后的部署动作代价 C_act 匹配 Source 成功候选的代价。两个状态的
> 匹配后 Action 候选**均通过**两步 C_2 认证（5/5）。
> 按预先冻结的解释边界，这支持：**原「仅 Source 能修复」的差异，可由 Action 候选族的
> 幅度覆盖不足解释，而非 Source 修正方向在相同动作代价下更有效。**

---

## 1. 范围（冻结）

- 只分析两个 source_only 状态（ep06/q28、ep07/q18），不增加状态。
- 取各状态按原规则选出的 Source 成功候选，计算其最终部署动作代价 C_act。
- 沿原 Action 修正方向调整幅度，使 clipping 后的 C_act 匹配该值。
- 匹配只查询动作代价，不查询认证结果。
- 每个状态一个匹配候选（统一缩放系数 s），按原五次重复 + 同一 C_2 评估。

## 2. 解释边界（预先冻结）

| 匹配后结果 | 支持的解释 |
|---|---|
| Action 成功 | 原独占修复差异可由候选幅度覆盖不足解释 |
| Action 仍失败 | 该状态上 Source 的修正方向在相同动作代价下更有效 |
| 结果翻转或不可达 | 该诊断无法明确归因 |

## 3. 结果

| 状态 | Source 成功候选 | target C_act | 匹配 s | 匹配后 C_act | residual | Action C_2 |
|---|---|---|---|---|---|---|
| ep06/q28 | source β=0.25 | 1.4405 | 9.962 | 1.4405 | 0.0000 | **5/5 通过** |
| ep07/q18 | source β=1.0 | 0.7576 | 1.073 | 0.7572 | 0.0003 | **5/5 通过** |

两个状态均 **action_success**。

### 3.1 为什么匹配系数很大（尤其 ep06）

- ep06：`da_norm=0.145`，原 Action β=1.0 的 C_act ≈ 0.145；而 Source β=0.25 的
  C_act 高达 1.440。因为 Source 候选经非线性策略前向，即使源空间 β 很小（0.25），
  映射到动作域的偏离也很大（1.44）——**源空间小步长 ≠ 动作域小修正**。
- 匹配需 s≈9.96（约 10 倍于原 Action 候选族最大幅度），放大后 Action 也修复。
- ep07：`da_norm=0.715`，Source β=1.0 的 C_act=0.758，只需 s≈1.073（略超 1.0）。

## 4. 解释（按冻结边界）

**Action 成功 → 原独占修复差异可由候选幅度覆盖不足解释。**

- 两个 source-only 状态的「仅 Source 能修复」，源于原 Action 候选族 β∈{0.25,0.5,0.75,1.0}
  的幅度覆盖不足（ep06 尤甚），而非 Source 的修正方向在相同动作代价下更有效。
- 当把 Action 沿同一方向 Δa* 放大到与 Source 相同部署代价时，Action 同样清除碰撞。

## 5. 对主结论的影响

- **不改写** 12 状态批次结论（未建立 Source 系统性优势、停止扩大方案）。
- 进一步**削弱**「Source 有独占修复能力」的机制主张：两个 source-only 案例都可被
  幅度放大的 Action 覆盖，Source 的「独占性」是候选族幅度设计的人为产物，
  不是方向优势。

## 6. 局限

- 只覆盖 2 个 source-only 状态，不覆盖 action-only（ep10）或 neither 状态。
- 匹配沿固定的最小范数 Δa* 方向；不排除其他 Action 方向在更低代价下修复的可能。
- C_act 是部署 pose 相对 nominal 的 L2（未加权），匹配残差 < 0.0004。
- 本诊断属于探索性解释分析，不进入批次统计，不追加方向、状态或预算。
