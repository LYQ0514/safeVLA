# P1 修正：跨进程数值差异 sentinel 量化

- **日期**：2026-10-31
- **目的**：按想法v11，量化跨进程数值差异，更正 P1 验收记录

---

## 一、结论

跨进程数值差异**存在但很小，不导致事件级翻转**。

| 验收项 | 状态 |
|---|---|
| 源噪声身份与调度 | PASS（z_sha256 跨进程完全一致）|
| 跨进程 action 逐字节一致性 | FAIL（max_abs_error ≈ 0.0085）|
| 动作数值近似可复现性 | 已量化：~0.85% 量级 |
| CAR/接触/成功事件可复现性 | 已量化：car_flip=False, mechanism_flip=False |

---

## 二、层 1：固定输入推理误差（同 z 跨 worker）

5 次独立 worker 加载，同一 z 推理：

```
max_abs_error = 0.00849   （动作值范围 [-1,1]，即 0.85% 量级）
max_rel_l2    = 0.00725   （相对 L2 误差 0.73%）
```

根因（推断，未完全确定）：JAX 在 GPU 上的浮点运算非确定（bfloat16 归约顺序
可能随 CUDA 初始化状态变化）。想法v11 指出「不能将原因确定为 bfloat16」，
因此当前表述为「跨进程数值差异」，而非断言 bfloat16。

## 四、对 600 条扩展的结论

按「可重放源噪声 + 近似数值复现」的身份开展正式运行，**不需要开 GPU 确定性模式**：

1. 源噪声（z）完全确定（CRN 纯 CPU）；
2. 动作数值误差 ~0.85% 量级；
3. 事件级结果（CAR / 机制 / 接触）在 sentinel 上稳定不翻转。

若后续正式运行中发现个别 episode 出现事件翻转（如 CAR 触发边界在 1mm 附近），
再回退评估确定性配置，不直接改配置。
