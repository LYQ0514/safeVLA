## 0. 结论（回答决定性问题的答案）

> 外部安全规划能把机器人送到「安全预抓取姿态」（P0r2/P0e-r 已验证），但
> **冻结 π0.5 从这些侧倾姿态接管后，无法在保持安全的同时完成任务**。
> 三种接管失败模式同时出现：① π0.5 回到偏好路径撞 mug（S01 P-V，mug 撞飞 13mm）；
> ② HVNP 候选字典在侧倾姿态下方向失配、NVS 终止（S01/S09 P-H）；③ π0.5 从侧倾
> 姿态无法有效抓取（S04 P-V/P-H，跑满 550 步失败零碰撞）。

**核心判断**：几何可达 + 动力学可执行 **都不等于** 冻结 π0.5 可接管。研究重点应
转向「安全预抓取状态与冻结策略可接管性之间的匹配问题」。

## 2. 三种接管失败模式（精确归因）

### 模式 1：冻结策略偏好与安全状态冲突（S01 P-V）

π0.5 从侧倾预抓取姿态接管后**成功完成整个任务**（soup@144、成功@264），但过程
中 link6 与 mug 接触 34 次（首次@step57），mug 被撞飞 13mm。这说明 π0.5 从侧倾
姿态**试图回到它偏好的顶部抓取路径**，link6 擦过 mug——这正是原始 B 轨迹的
link6-mug 接触机制重现。

### 模式 2：HVNP 候选字典的姿态失配（S01/S09 P-H）

S01 P-H 的诊断（step164-168）精确揭示了失配：

| 候选 | 预测 Dmax | 判决 |
|---|---|---|
| N | 0.04-0.095mm | 不安全 |
| A | 32-43mm | 灾难性碰撞 |
| Z+A | 18-22mm | 灾难性碰撞 |
| L+A | 18-21mm | 灾难性碰撞 |
| Hold+N | 0（暂时）→ 0.012mm（step168）| 最终也失效 |

HVNP 的 A/Z+A/L+A 局部避让方向是为「原始朝下姿态」设计的，在「侧倾姿态」下
方向完全失配（产生 20-43mm 的碰撞而非避让），最终 NVS 终止。

### 模式 3：几何预抓取可行 ≠ 策略可接管（S04 P-V/P-H）

S04 的 P-V/P-H 都跑满 550 步、零碰撞、任务失败（soup 未抓取）。π0.5 从侧倾
姿态**无法有效抓取 soup**——不是碰撞问题，而是策略在非偏好姿态下无法产生有效的
抓取行为。

## 4. State02 正对照的「假成功」（重要方法学发现）

State02 P-V 报告「成功@step0」是**假成功**：关节 PD 执行阶段，机械臂碰到了
soup/cream（TASK 物体，非 forbidden），把它们撞进了 basket，导致 `check_success`
在 step0 误判 True。

这暴露了**第二个契约缺口**：当前安全契约只监控 PROTECTED（mug 等），**不监控
TASK 物体（soup/cream）的「被预抓取路径撞飞」**。虽然抓取 soup 需要接触，但
「预抓取阶段就撞飞 soup」明显不是合法行为。

**State02 正对照在此实验中失效**——它的「成功」来自路径执行阶段的物理错误，而非
π0.5 接续。且 P-V 与 P-H 结果相同（都假成功@step0），因为假成功发生在「接管前的
关节 PD 执行阶段」（两条分支共享同一预抓取路径），与接管后的 π0.5 行为无关。

## 5. 判决（按用户预设）

命中：

> **「P-V 能抓取、P-H 不能 → 研究安全过滤导致的任务可接续性损失」**（S01）
>
> 以及更根本的：**「几何可达 + 动力学可执行 ≠ 冻结 π0.5 可接管」**（S04 的
> 零碰撞失败、S01 的撞 mug 成功、HVNP 的姿态失配，三者共同指向这个结论）。

## 6. 对研究主线的最新定位

P4 研究线的三层验证链最终结果：

$$\underbrace{\text{Safe Reachability}}_{✅} + \underbrace{\text{Dynamic Executability}}_{✅} + \underbrace{\text{Frozen-VLA Re-entry}}_{❌}$$

**前两层成立，第三层失败**。这明确了下一步的核心问题：

> 外部规划的安全预抓取状态，**必须同时满足「冻结 π0.5 愿意接续」**。单纯把
> 机器人送到无碰撞姿态不够——π0.5 可能（a）回到偏好路径撞障碍物，（b）在非
> 偏好姿态下无法抓取。

这指向「可行性感知安全干预」的完整定义：**可达性 + 可执行性 + 可接管性三者
联合**，而非独立。

## 7. 需要修复的第二个契约缺口

TASK 物体的「预抓取阶段被撞飞」需纳入监控：
- soup/cream 在「非抓取阶段」的位移应被检测（区别于合法抓取接触）；
- State02 的假成功正说明，若不监控，会误报任务成功。

## 8. 诚实边界

- 只测了 3 困难状态 + 1 正对照，非统计结论；
- State02 正对照失效（假成功，见 §4），不构成有效正对照；
- 侧倾姿态来自固定朝向集合，不排除存在「π0.5 更愿接续」的其他安全姿态；
- S01 P-V 的 13mm 撞飞是严重违规，但任务「成功」本身是真实的（soup+cream 都放置成功）。
