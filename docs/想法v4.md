可以开始分层 relabel audit，但先修正一个统计单位问题：`547 vs 24` 目前不能直接解释为“漏检 23 倍”。

原因是：

- 547 可能是 25 个 physics substep 上重复累计的 contact records；
- 24 是 control-step 结束时的 snapshots；
- 比值 \(547/24\approx22.8\)，恰好接近每步 25 个 substeps。

这可能只是同一持续接触被重复记录约 25 次，而不一定表示漏掉了 23 倍的碰撞事件。

## 先补一个归一化对照

对每个 control step \(j\) 定义：

\[
Y_{\rm sub}(j)=
\mathbf1[\text{该步任一 physics substep 出现 forbidden contact}],
\]

\[
Y_{\rm end}(j)=
\mathbf1[\text{env.step 返回时仍存在 forbidden contact}].
\]

然后报告四格表：

| | `Y_end=0` | `Y_end=1` |
|---|---:|---:|
| `Y_sub=0` | TN | FP |
| `Y_sub=1` | FN：瞬时接触被漏掉 | TP |

真正能证明 step-end 漏检的是：

```text
Y_sub=1 且 Y_end=0 的 control-step 数
```

不是 raw contact-record 数量之比。

同时增加：

```text
total_control_steps
total_physics_substeps
steps_with_any_substep_contact
steps_with_endpoint_contact
episodes_with_any_substep_contact
episodes_with_endpoint_contact
contiguous_contact_event_count
contact_duration_substeps
unique_forbidden_geom_pairs
minimum_contact_dist
```

其中 `contiguous_contact_event_count` 应把连续 substeps 上同一 geom pair 的接触合并成一次事件。

## 还要确认“547 次”确实是 forbidden contact

请输出 pair 分布，例如：

```text
robot_link ↔ red_coffee_mug
robot_link ↔ table
gripper ↔ target
target ↔ obstacle
robot self-contact
```

过滤必须同时满足：

- collision-compatible geom pair；
- 正确的 robot/target/obstacle body 集合；
- 阶段接触规则；
- 排除允许的 robot–target 与 target–goal 接触；
- 主接触口径建议要求 `contact.dist <= 0`；
- 初始已经存在的接触单独记录。

否则 547 可能混入持续的桌面、目标物体或允许接触。

## 分层 relabel audit 可以启动

建议冻结三个并列标签：

```text
Y_L1       = legacy displacement event
Y_endpoint = step-end forbidden contact
Y_substep  = any-substep forbidden contact
```

主目标是估计：

```text
Y_L1 vs Y_substep
Y_endpoint vs Y_substep
```

不要只研究旧 `Y_L1=1` 的 episode，还要加入旧 non-collision 对照，否则无法估计 false-negative rate。

### 抽样层

同时按 task/episode 分层，统计单位使用独立 episode，不能把同一 episode 的多个 contact steps 当作独立样本。

每个单元先抽固定数量做设计审计；样本不足时全部纳入。抽样 seed 必须冻结。

## 审计后的分类

每条 episode 分为：

```text
TRUE_FORBIDDEN_CONTACT
TRANSIENT_CONTACT_MISSED_AT_STEP_END
LEGACY_DISPLACEMENT_ONLY
SCENE_PHYSICS_UNSTABLE
INITIAL_PENETRATION
LEGACY_FALSE_NEGATIVE
NONREPRODUCIBLE
```

其中：

- `Y_L1=1, Y_substep=0, stability=PASS`：位移法假阳性；
- `Y_L1=0, Y_substep=1`：位移法假阴性；
- `Y_endpoint=0, Y_substep=1`：step-end 检测漏掉瞬时接触；
- zero-action 也发生大位移：场景不稳定，不能归因于方法。

## 三方 CAR 的处理

当前三个历史数字继续标记为：

```text
LEGACY_DISPLACEMENT_METRIC_PENDING_CONTACT_RECONCILIATION
```

但“必须全部重跑”的最终依据应是以下任一项，而不是 `547/24`：

1. 历史数据无法重建 `Y_substep`；
2. `Y_endpoint` 对 `Y_substep` 存在实质性 episode-level 漏检；
3. `Y_L1` 的假阳性或假阴性率较高；
4. 三种方法的误分类率不同；
5. 换用 `Y_substep` 后方法排序或效果量明显改变；
6. 历史动作无法可靠 replay。

如果历史日志没有 substep contact，那么新的真实接触 CAR 确实只能通过重新运行获得；旧摘要无法离线补出遗漏的瞬时接触。
