# PNSG v1.3 当前方法完整说明与独立实现规格

## 1. 方法的核心目标

给定冻结策略、当前环境状态和策略源噪声，PNSG研究的不是“动作空间里能否随便找到一个安全动作”，而是：

> 在策略自身的生成源空间中，找到代价尽量小、仍保留策略结构、并能通过真实非线性安全认证的动作修正。

设冻结的 π0.5 策略生成映射为

[
A_{\rm ext}=T_{\rm external}(z;s),
]

其中：

- (s)：当前环境状态及观测；
- (z\in\mathbb R^{H\times d_z})：Flow Matching 初始源噪声；
- 当前配置中 (H=10,\ d_z=32)，所以源空间总维数为 320；
- (A_{\rm ext}\in\mathbb R^{H\times 7})：外部动作 chunk；
- 前六维为 pose 通道，最后一维为 gripper 通道。

真正部署到 LIBERO 控制器的映射为

[
T_{\rm deploy}(z;s)
=\operatorname{clip}\bigl(T_{\rm external}(z;s),-1,1\bigr).
]

当前线性分析使用 clipping 前的局部 Jacobian；非线性候选验证和真实执行使用 clipping 后动作。因此 clipping 是部署系统的一部分，而不是事后应删除的“异常样本”。

## 2. PNSG 要测量的三个量

### 2.1 线性可修复半径

在名义噪声 (z_0) 附近，计算满足局部安全代理所需的最小源空间修正：

\min_{\Delta z}|\Delta z|_2
\quad
\text{s.t.}\quad
A\Delta z\ge b.
]

### 2.2 预算归一化难度

\frac{r_{\rm crit}^{\rm lin}}{r_{\rm budget}},
\qquad
r_{\rm budget}=12.
]

解释：

- (\chi_{\rm lin}\le1)：在线性模型下，预算内存在修正；
- (\chi_{\rm lin}>1)：线性模型预测需要超过预算；
- (\chi_{\rm lin}) 不是非线性可行性的证明；
- (\chi_{\rm lin}>1) 不能直接解释为“状态不可修复”。

### 2.3 源空间代价

对确实从同一个 (z_0) steering 得到的候选：

\frac12|z-z_0|_2^2.
]

这是样本级源位移代价，不是 KL，也不能用于独立重采样候选。

## 3. 策略 Jacobian

对冻结状态 (s) 和名义噪声 (z_0)，计算 pose action 对源噪声的 Jacobian：

D_z\operatorname{vec}
\left(T_{\rm external}(z;s)*{:,0:6}\right)\bigg|*{z=z_0}
\in\mathbb R^{60\times320}.
]

推荐接口：

```
actions, J = policy.generate_with_jacobian(
    observation=obs,
    source_noise=z0,
)
```

其中：

```
actions.shape = (10, 7)
J.shape       = (60, 320)
```

要求：

1. Jacobian 必须对应外部 pose 动作坐标；
2. 必须包含 output unnormalization 的 affine scaling；
3. 不应包含 clipping 的不可微跳变；
4. 部署候选仍必须经过 clipping；
5. 必须用 JVP 或有限差分做自检。

当前代码的转换形式为：

```
external_J = raw_J * action_scale
```

然后将 10×6 pose 输出和 10×32 source 输入展平。

独立实现时不要依赖另外拟合的 raw-action map。最好让动作输出和 Jacobian 共用同一个显式 transform 函数。

## 4. 几何代理模型

## 4.1 机器人控制点

当前快速代理不是单个末端点，而是机器人 collision geoms 的球体覆盖：

- capsule / cylinder：沿轴线放置若干球；
- box：使用若干代表性球；
- 其他 geom：使用 `geom_rbound`；
- 控制点覆盖机械臂和夹爪相关碰撞几何。

每个控制点 (k) 保存：

[
p_k^0\in\mathbb R^3,\qquad
B_k\in\mathbb R^{3\times6},\qquad
r_k.
]

其中 (B_k) 是固定当前状态下，控制点位置相对于六维 pose action 的局部有限差分 Jacobian。

## 4.2 障碍物代理

当前注册的 pillar 类障碍物使用四个重叠球表示：

[
(o_q,R_q),\qquad q=1,\ldots,4.
]

其他物体可能使用有限数量的 bounding-sphere 回退。这不是完整 MuJoCo collision geometry，也没有确定性包络证明。

## 4.3 离散轨迹

对候选 pose action (a_t^{pose})，预测控制点位置：

p_k^0+
\sum_{\ell=0}^{t}B_k a_\ell^{pose}.
]

球体代理净空为

|p_{t,k}-o_q|_2-r_k-R_q.
]

目标代理净空为

[
h=0.005\ {\rm m}.
]

## 5. 线性安全约束

在名义动作 (A_0=T_{\rm external}(z_0;s)) 处，对每个选中的约束 (i=(t,k,q))：

[
b_i=h-g_i(A_0).
]

令

[
n_i=
\frac{p_{t,k}-o_q}
{|p_{t,k}-o_q|_2}.
]

该约束对各 pose action 的协向量为

\begin{cases}
B_k^\top n_i,&\ell\le t,\
0,&\ell>t.
\end{cases}
]

展平后 (c_i\in\mathbb R^{60})。源空间约束为

[
(c_i^\top J)\Delta z\ge b_i.
]

堆叠所有约束得到

[
A=CJ,\qquad A\in\mathbb R^{m_c\times320}.
]

注意：

- (C) 是动作空间几何协向量；
- (J) 是策略生成映射 Jacobian；
- (A=CJ) 才是源空间可修复约束；
- (b_i\le0) 表示名义动作对该约束已经满足目标净空。

## 6. 两种代理索引集

### 6.1 Fast 索引

[
I_{\rm fast}=I_{\rm fast}(s,z_0).
]

当前实现：

- 在名义候选 (z_0) 上选约束；
- 按净空从小到大排序；
- 最多取 3 条；
- 通常保留到 (h+0.01) m；
- 后续求解期间索引集固定。

这是当前 H-Fast 求解器使用的索引集。

### 6.2 Wide 索引

修正后的正确口径是：

[
I_{\rm wide}=I_{\rm wide}(s,z).
]

即每个候选动作都重新运行代理筛选。当前参数：

```
target_clearance = 0.005 m
maximum_constraints = 600
margin = 10.0
```

因此它是候选依赖的宽代理检查，不是固定的完整索引宇宙。

### 6.3 Full 索引

[
I_{\rm full}
]

目前只有规格，没有实现。它应当：

- 有版本化的完整索引清单；
- 不受 600 条容量上限截断；
- 明确覆盖全部机器人、目标物体和障碍物组合；
- 具有可审计的完备性测试。

禁止把 (I_{\rm wide}) 称为 (I_{\rm full})。

## 7. H-Fast 最小范数求解

当前核心求解问题为

\arg\min_{\Delta z}\frac12|\Delta z|_2^2
\quad\text{s.t.}\quad
A\Delta z\ge b.
]

由于 Fast 最多只有三条约束，当前实现枚举所有非空 active set。

对 active set (\mathcal A)：

(A_{\mathcal A}A_{\mathcal A}^\top)^+
b_{\mathcal A},
]

A_{\mathcal A}^\top\lambda_{\mathcal A}.
]

接受条件：

1. (\lambda_{\mathcal A}\ge0)；
2. (A\Delta z_{\mathcal A}\ge b-\varepsilon)；
3. 在所有可行 active set 中取范数最小者。

伪代码：

```
def minimum_norm_halfspaces(A, b, tol=1e-9):
    if all(b <= tol):
        return zeros(A.shape[1])

    best = None

    for active_set in all_nonempty_subsets(range(len(b))):
        Aa = A[active_set]
        ba = b[active_set]

        lam = pinv(Aa @ Aa.T) @ ba
        if any(lam < -tol):
            continue

        dz = Aa.T @ lam
        if all(A @ dz >= b - tol):
            if best is None or norm(dz) < norm(best):
                best = dz

    return best
```

得到：

[
r_{\rm crit}^{lin}=|\Delta z^\star|_2.
]

## 8. 线性不可行性与 Farkas witness

如果线性系统可能不可行，不能用 `rank(J)` 代替不可行性证明。

应搜索

[
y\ge0,\qquad \mathbf1^\top y=1,
]

满足

[
|A^\top y|\le\varepsilon_{\rm null},
\qquad
b^\top y>\varepsilon_{\rm margin}.
]

找到这样的 (y) 才记录显式 Farkas witness。

含义：

- witness 存在：当前线性约束系统不可行；
- witness 不存在：不等于已经证明可行；
- `rank(J)<60` 本身不是 Farkas 证书。

## 9. 候选生成

## 9.1 最小实现

第一版建议只生成以下候选：

```
A. nominal：z0
B. direct proposal：z0 + Δz*
C. scaled proposals：z0 + αΔz*
```

冻结

[
\alpha\in{0.25,0.5,0.75,1.0}.
]

对每个候选都重新调用策略：

```
candidate = policy.generate(
    observation=obs,
    source_noise=z0 + alpha * delta_z,
)
candidate = clip(candidate, -1, 1)
```

不能用

[
A_0+J\Delta z
]

代替真实策略重新前向。线性式只用于生成 proposal，不用于最终动作。

## 9.2 非线性半径搜索版本

当前 RQ2 仪器还使用与 (r_{\rm budget}) 判定解耦的搜索：

```
radius multipliers:
0,
0.015625, 0.03125, 0.0625, 0.125,
0.25, 0.5, 1, 2, 4, 8

directions: 8
candidate count: 1 + 10×8 = 81
```

令

[
d_0=\frac{\Delta z^\star}{|\Delta z^\star|}.
]

生成与 (d_0) 正交的随机切向量 (u_j)，然后

[
d_j=
\frac{d_0+w_j u_j}
{|d_0+w_j u_j|}.
]

候选源变量：

[
z_{r,j}=z_0+r,r_{\rm budget}d_j.
]

这一搜索主要用于测量非线性首次成功半径，不是当前已验证的在线算法。

不能把搜索半径限制为 (r_{\rm budget}) 后再用它验证 (\chi_{\rm lin}>1)，否则会形成循环论证。

## 10. 非线性认证器 (C_2)

代理通过不能直接获得执行许可。

当前认证事件 (C_2) 定义为：

> 从同一个完整仿真状态恢复，执行候选的前两个动作，通过真实 robosuite 控制器推进 MuJoCo，并在全部可观察 simulator substeps 上检查统一安全条件。

认证至少检查：

1. robot–obstacle 禁止接触；
2. 相对初始状态新增的 robot self-collision；
3. grasped target–obstacle 禁止接触；
4. robot–target、target–goal 的阶段接触规则；
5. joint position limits；
6. actuator control limits；
7. external action limits；
8. Panda velocity contract；
9. collision-compatible geom pairs 的 MuJoCo 几何距离；
10. 最小真实净空不小于 0。

注意：

[
C_2\text{ 的几何阈值是 }0\ {\rm mm},
]

而代理 (S_{\rm wide}) 的目标是 5 mm。两者既不等价，也不存在已证明的确定性包含关系。

认证前必须执行：

```
snapshot = save_full_state(env)
restore_full_state(env, snapshot)
```

每个候选都从完全相同的状态开始，不能连续在同一个 env 上顺序执行候选。

## 11. 事件契约

### 11.1 Fast 代理事件

[
S_{\rm fast}(s,z)=
\mathbf1\left[
\bigwedge_{i\in I_{\rm fast}(s,z_0)}
G_i(T_{\rm deploy}(z;s);s)\ge h
\right].
]

### 11.2 Wide 代理事件

[
S_{\rm wide}(s,z)=
\mathbf1\left[
\min_{i\in I_{\rm wide}(s,z)}
G_i(T_{\rm deploy}(z;s);s)\ge0.005
\right].
]

### 11.3 当前旧实现接受事件

[
E_{\rm impl_old}=S_{\rm wide}\land C_2.
]

当前代码中的 `deployable_aligned_success` 对应这个事件。

### 11.4 目标进度事件

目标规格为

[
P_H(s,z)=
\mathbf1\left[
\Phi_{\sigma(s)}(\hat x_H)
\le
\Phi_{\sigma(s)}(x_0)-\epsilon_{\sigma(s)}
\right].
]

它要求在执行前，使用冻结的预测模型判断完整 (H=10) chunk 是否产生阶段进度。

当前尚未实现 (P_H)。

### 11.5 目标接受事件

[
E_{\rm acc}=C_2\land P_H.
]

### 11.6 完整部署事件

S_{\rm wide}\land C_2\land P_H.
]

因此当前 `deployable_aligned_success` 不能称为 (E_{\rm acc}) 或完整 PNSG 接受事件。

## 12. 系统进度

历史 Phase 0 使用真实 `env.step()` 后的状态变化判断进度：

- approach：EEF 到 target 距离下降；
- grasp：新接触、抬升或 EEF 距离下降；
- transport：target 到 goal 距离下降；
- place：新 goal contact 或 goal 距离下降；
- task success：直接记为 progress。

历史阈值为 2 mm。

这个量是执行后系统结果，不是执行前的 (P_H)。独立实现时应分别命名：

```
P_H_model       执行前预测进度
Prog_sys        执行后真实进度
```

不得互换。

## 13. 动作空间基线与策略度量

动作空间最小修正基线为

\arg\min_{\Delta A}\frac12|\Delta A|_2^2
\quad
\text{s.t.}\quad C\Delta A\ge b.
]

给定动作修正 (\Delta A)，其局部最小源代价代理为

\frac12
\Delta A^\top(JJ^\top)^+\Delta A,
]

前提是 (\Delta A) 位于或接近 (\operatorname{range}(J))。

这不是 realized (C_{\rm src})，而是局部最小源位移代理。

可用于比较：

```
identity metric:  ||ΔA||²
policy metric:    ΔAᵀ(JJᵀ)⁺ΔA
```

## 15. 主流程伪代码

```
def pnsg_step(env, policy, obs, config):
    # 1. 固定状态和源噪声
    snapshot = save_full_state(env)
    z0 = sample_or_load_source_noise(config.seed, shape=(10, 32))

    # 2. 名义动作与 Jacobian
    nominal, J = policy.generate_with_jacobian(obs, z0)
    nominal_deploy = clip(nominal, -1, 1)

    # 3. 几何代理
    guide = build_geometry_proxy(env, obs)
    fast_rows = selected_constraints(
        nominal_deploy[:, :6],
        guide,
        h_floor=0.005,
        maximum_constraints=3,
        margin=0.01,
    )

    C = stack([row.covector for row in fast_rows])
    b = array([0.005 - row.clearance for row in fast_rows])
    A = C @ J

    # 4. 最小源空间修正
    delta_z = minimum_norm_halfspaces(A, b)
    farkas = farkas_certificate(A, b)

    if farkas.found or delta_z is None:
        return "LINEAR_REPAIR_UNAVAILABLE"

    rcrit = norm(delta_z)
    chi = rcrit / 12.0

    # 5. 候选池
    source_candidates = [
        ("nominal", z0),
        ("alpha_025", z0 + 0.25 * delta_z),
        ("alpha_050", z0 + 0.50 * delta_z),
        ("alpha_075", z0 + 0.75 * delta_z),
        ("alpha_100", z0 + 1.00 * delta_z),
    ]

    results = []

    for candidate_id, z in source_candidates:
        actions = policy.generate(obs, z)
        actions = clip(actions, -1, 1)

        # 候选依赖 wide 代理
        wide_rows = selected_constraints(
            actions[:, :6],
            guide,
            h_floor=0.005,
            maximum_constraints=600,
            margin=10.0,
        )
        S_wide = min(row.clearance for row in wide_rows) >= 0.005

        # 同状态非线性认证
        restore_full_state(env, snapshot)
        C2 = certify_prefix(env, actions[:2])

        # P_H 若未实现，必须记 NA
        P_H = None

        results.append({
            "candidate_id": candidate_id,
            "z": z,
            "source_delta_norm": norm(z-z0),
            "C_src": 0.5 * norm(z-z0)**2,
            "actions": actions,
            "S_wide": S_wide,
            "C_2": C2.pass_,
            "P_H": P_H,
            "E_impl_old": S_wide and C2.pass_,
            "E_acc": None,
            "chi_lin": chi,
        })

    return results
```

## 17. 实现后的必要测试

### 17.1 策略映射

- 固定 (s,z_0)，重复前向动作完全一致；
- 注入同一个 (z_0) 得到同一 raw action；
- output transform 只执行一次；
- Jacobian 坐标与外部动作一致；
- clipping 前后分别记录。

### 17.2 Jacobian

对随机单位方向 (v)：

[
Jv
\approx
\frac{T(z_0+\epsilon v)-T(z_0-\epsilon v)}
{2\epsilon}.
]

至少报告：

- 绝对误差；
- 相对误差；
- cosine similarity；
- (|Jv|) 与差分尺度。

### 17.3 状态恢复

同一 snapshot、action、RNG 重复执行，比较：

- qpos；
- qvel；
- object poses；
- observation；
- reward；
- contact；
- task stage。

### 17.4 求解器

构造可解析的 1、2、3 约束合成问题，检查：

- KKT 条件；
- active set；
- primal feasibility；
- 与通用 QP 解一致；
- Farkas witness 残差。

### 17.5 代理与认证

分别测试：

- (S_{\rm wide}=1,C_2=1)；
- (S_{\rm wide}=1,C_2=0)；
- (S_{\rm wide}=0,C_2=1)；
- (S_{\rm wide}=0,C_2=0)。

如果只出现一种组合，仪器可能饱和，不能据此评估预测能力。

## 19. 推荐的独立复现顺序

### 第一步：只实现核心 proposal

完成：

[
J,\ C,\ b,\ A=CJ,\ \Delta z^\star,\ r_{\rm crit},\chi_{\rm lin}.
]

用合成约束和单个真实状态验证。

### 第二步：接真实策略重新前向

比较：

```
nominal
z0 + 0.25Δz
z0 + 0.5Δz
z0 + 0.75Δz
z0 + Δz
```

记录代理净空、clipping 和动作变化。
