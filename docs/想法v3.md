当前最优先的确是修正碰撞评测基础，但不要立刻把 L1 改成 L2 后重算 CAR。应先完成“碰撞事件身份审计”，因为目前关于 L1 的解释还有一个数学矛盾。

## 先纠正一个关键判断

对同一个三维位移向量 \(d\)，必有：

\[
\|d\|_2\le \|d\|_1\le\sqrt3\|d\|_2.
\]

因此，如果同一轨迹、同一时刻满足：

\[
\|d\|_1>1\text{ mm},
\]

那么必然有：

\[
\|d\|_2>0.577\text{ mm}.
\]

不可能同时出现“L1 超过 1 mm、L2 真正等于 0”。你看到的 `0.00mm` 可能来自：

- 输出精度截断；
- 两次 replay 的动作或随机种子不完全一致；
- initial position 取值时刻不同；
- position measurement frame 不同；
- baseline 筛选器记录的不是你后来检查的同一个 body；
- 筛选脚本统计了累计/峰值，而复查脚本只打印当前值。

此外，0.3 mm 级漂移不是通常意义上的浮点舍入噪声。它更可能是接触求解、物体沉降、控制器扰动或 reset 差异。

所以当前能确认的是：

> legacy 的 L1 位移阈值不是可靠的碰撞定义；但尚不能确认 task2 ep16 的旧标签纯粹来自浮点噪声。

## 第一步：同一次 rollout 同时记录 L1 和 L2

不要再比较两次独立 replay。对同一 action sequence 同时记录：

```python
delta = current_position - initial_position
l1_mm = 1000 * np.linalg.norm(delta, ord=1)
l2_mm = 1000 * np.linalg.norm(delta, ord=2)

assert l2_mm <= l1_mm + 1e-9
assert l1_mm <= np.sqrt(3) * l2_mm + 1e-9
```

同时保存：

```text
episode
step
body_name
initial_position
current_position
delta_xyz
L1
L2
action_hash
policy_seed
noise_seed
initial_state_hash
```

如果两次复现的 action hash 不同，就不能用后一次 replay 推翻前一次标签。

## 新碰撞定义不要使用“L2 + 更高阈值”

L2 比 L1 更适合作为位移严重度，但它仍然不能判断因果碰撞。物体可能因为：

- 自身沉降；
- obstacle–environment 接触；
- 初始穿透；
- 被目标物体推动；
- 被机器人推动；
- 数值不稳定；

而发生相同的 L2 位移。

因此推荐冻结三层指标。

### 1. 主碰撞事件

在每个 MuJoCo simulator substep 检查：

\[
C_{\rm robot}
=
\mathbf1[
\exists\text{ forbidden robot–obstacle geom pair with }contact.dist\le0
].
\]

抓取阶段另报：

\[
C_{\rm target}
=
\mathbf1[
\exists\text{ forbidden target–obstacle geom pair with }contact.dist\le0
].
\]

必须使用 substep recorder，不能只在 `env.step()` 返回后查看 `data.contact`。

### 2. 场景不稳定事件

从相同 snapshot 执行 hold/zero-action：

```text
初始穿透
obstacle–environment contact
无机器人接触时的大位移
自发弹飞
```

命名为：

```text
SCENE_PHYSICS_UNSTABLE
```

不要归入机器人碰撞。

### 3. 严重度指标

仅作为结果严重程度报告：

```text
peak translational L2 displacement
final translational L2 displacement
rotation geodesic angle
minimum native geom distance
contact duration
maximum penetration
```

原来的 L1 指标改名：

```text
legacy_obstacle_displacement_event
```

不要继续称为 collision。

## CAR 暂时不要直接重算

正确顺序是先做小规模 relabel audit，判断旧 CAR 到底受多大影响。

### 分层抽样

从每种方法分别抽取：

```text
legacy L1 1.0–1.5 mm
1.5–3 mm
3–5 mm
5–50 mm
>50 mm
旧标签为 non-collision 的对照
```

并覆盖 π0.5、AEGIS、VLPSA 和不同任务。

每条 replay 输出：

| 字段 | 含义 |
|---|---|
| legacy_L1_event | 旧指标 |
| L2_peak | 位移严重度 |
| robot_obstacle_contact | 主真实碰撞 |
| target_obstacle_contact | 抓取物碰撞 |
| initial_penetration | 初始场景问题 |
| zero_action_unstable | 场景物理伪影 |
| first_contact_pair | 首次接触身份 |
| first_contact_step/substep | 时间 |
| action_hash_match | replay 是否复现历史动作 |

然后为每种方法分别计算：

```text
旧 L1 标签 vs robot contact 的混淆矩阵
旧 L1 标签 vs target contact 的混淆矩阵
scene instability rate
near-threshold false-positive rate
历史 action 可复现率
```

## 什么时候必须重跑三方 CAR

出现下列任一情况，就不能只做数值修补，必须按新定义重新跑正式评测：

1. 旧数据没有 simulator-substep contact 记录；
2. 历史 action sequence 无法确定性复现；
3. 三种方法的旧标签误报率明显不同；
4. 新口径改变三方方法排序；
5. AEGIS 相对 π0.5 的效果主要集中在 1–2 mm 阈值附近；
6. `SCENE_PHYSICS_UNSTABLE` 在方法间分布不均；
7. target–obstacle 与 robot–obstacle 被旧指标混为一类。

若旧数据没有接触 provenance，那么不能把旧 CAR “换公式重算”为新 CAR；只能将旧值保留为：

```text
legacy displacement-based avoidance rate
```

新实验另报：

```text
forbidden-contact avoidance rate
```

## 对当前三个数字的正确状态

现在应记录为：

```text
π0.5 CAR 13.8%
AEGIS CAR 60.4%
VLPSA CAR 19.8%
```

均属于：

```text
LEGACY_DISPLACEMENT_METRIC_PENDING_CONTACT_RECONCILIATION
```

暂时不能说它们错误，也不能继续把它们解释为真实 robot-obstacle collision avoidance。

同样，目前只能说：

> 443/1380 个 legacy displacement events 位于 1–1.5 mm 附近，因而对旧阈值高度敏感。

不能说这 443 个“大部分是浮点噪声”，因为还没有 contact-pair 与同轨迹 L1/L2 证据。

PNSG 大规模评测继续暂停，但 steering 机制验证仍然有效：

下一步不是继续找正对照，而是：

1. 修正同轨迹 L1/L2 记录；
2. 冻结 substep forbidden-contact 事件；
3. 做分层 relabel audit；
4. 判断旧三方实验是否需要正式重跑；
5. 从确认过的 robot/target–obstacle 接触中选择 PNSG 正对照。

这一步是当前最高优先级。否则继续筛 episode 只是在一个未经验证的标签集合里寻找“正例”。
